## 0. 一页结论

1. **值得立项，但必须先补口径。** 业务负责人顾明岚给出的目标明确且可量化：退货到退款平均时长 **6 天 → 3 天**，状态催问占比 **42% → 20%**；验收硬门槛为**状态解释准确率 99%、未验收自动退款为零**，首期预算 **15 万元**。目标与门槛都成立，但"6 天"和"42%"目前**没有节点级拆分与分母定义**，现在立项会把责任段混在一起。
2. **真正的瓶颈不在"处理慢"，而在"签收之后到排上质检之前"这段无人打点、无人对外的空窗。** 物流侧已显示仓库签收，WMS 未产生质检排队状态，售后客服台也查不到，客服只能凭经验口头解释（f10、f30、f50）。
3. **一线要的不是"更聪明的回答"，而是"可被引用的原记录"。** 林亦舟明确：建议必须显示对应原记录和待确认字段，看不到依据的不采信；异常件只能提示、不能替他下结论（f15）。
4. **三条红线已由风险岗具名确认：** 只读订单与售后、不自动退款、不自动认定欺诈；涉及最终决定、对外承诺、资产变更必须由审批人确认，不得借用账号（f32、f41）。傅景对上线**有否决权**（f04）。
5. **阶段关卡建议"有条件通过"：** 放行进入 02 现场调研，但把"42% 的分母""6 天的起止点""三种完成口径的对外用法"列为必须在 02 阶段闭环的补证项。

## 1. 项目背景与触发事件

### 1.1 业务背景

万象优选日均处理退货包裹约 **1500 件**，主流程为：

> 退货申请 → 寄回 → 仓库签收 → 商品验收 → 退款审批 → 客户通知

三套系统各自维护账号与状态：**OMS（订单）、WMS（仓储）、售后客服台（服务）**，业务状态没有统一视图（f30）。管理层希望用 AI 改善，但优先环节、验收标准、权限边界三项均未确定。

### 1.2 触发事件（最近一次异常）

| 要素 | 记录 |
| --- | --- |
| 事件 | 消费者退货包裹物流显示"仓库已签收"，但质检尚未排到，消费者反复催问"为什么还没退款" |
| 发生位置 | 仓库退回核验区 → 售后客服台 |
| 涉及岗位 | 退货质检员（林亦舟）、售后工单员（唐映秋）、消费者服务主管（叶书团队） |
| 现状表现 | 客服查不到"已签收、待质检"这一中间态；质检员只能说"还没轮到"；客户得到的解释无法核对 |
| 次生异常 | 一个包裹对应多个订单、退回件数量与申请不一致，需停下核对（f11） |
| 证据 | 电商-004 访谈事实记录（f10）、电商-016 访谈事实记录（f50）、电商-010 访谈事实记录（f30） |

### 1.3 功能诉求 ≠ 业务结果

| 客户/内部提出的说法 | 性质 | 真正要改善的业务结果 |
| --- | --- | --- |
| "做个能答客户'到哪了'的机器人" | 功能诉求 | 签收后等待可解释，状态催问占比 42% → 20% |
| "把三套系统的数据打通" | 技术手段 | 退货到退款 6 天 → 3 天，且能定位到责任段 |
| "让 AI 自动判退款" | **越界诉求** | 明确排除：不自主退款、不处罚账号（f05、f52） |
| "异常件自动处理" | 功能诉求 | 一包多单 / 数量不符的件能被识别、暂停、转交并留痕（f11、f15、f44） |

> 判断依据：指南要求"区分客户口头提出的功能诉求和真正要改善的业务结果"。本项目四条诉求中，只有第 2、4 条能对应到可测量的业务结果；第 3 条触红线，必须写进排除范围。

### 2.2 机会取舍建议

- **首期主机会：O1。** 它同时命中两个业务指标（时效、催问占比），且是概率最高、可只读实现的切入点（f05 明确"售后状态解释与异常分派"，先历史资料回放）。
- **必须配套：O2。** 状态解释准确率 99% 的前提是异常件不被"猜"过去；异常不识别，99% 无法达成。
- **必须先做、但不作为 AI 功能：O3。** 口径不统一，6 天与 42% 都无法验收，属于基线前置条件。
- **纳入方案边界：O4、O5。** 不单独做功能，但要写进"人工兜底与留痕"要求。
- **排除：自主退款、账号处罚、对客承诺具体时效**（f05、f52、f41）。

### 3.3 价值假设与测算

**假设链（每一环都可被推翻，必须逐环验证）：**

```
催问量/日 = 退货包裹量/日 × 催问占比
          = 1500 × 42% = 630 次/日            ← 前提：42% 的分母是"退货包裹数"

目标催问量/日 = 1500 × 20% = 300 次/日
减少催问量     = 330 次/日
节省工时       = 330 × 4 分钟 = 1,320 分钟 = 22.0 小时/日
```

> **必须写进报告的限定条件：**
> 1. 42% 的分母**尚未确认**。若分母是"售后咨询总量"，则上述总量测算不成立，只能按"每 100 次咨询节省 88 分钟"的单价口径计算（42→20，减少 22 次 × 4 min）。

**关键结论：决策链只能问出来，查不出来。** 本次确认到三个要点：
1. 顾明岚能定"做什么、做到什么程度"，**定不了"能不能上线"**——否决权在傅景（f04）。
2. 服务结果不是顾明岚一个人说了算，叶书参与验收（f04、f52）。
3. 任何一方不点头，方案推不下去；因此风险审核节点与服务验收节点必须**前置写进试点方案**，不能跑完再补（顾明岚原话）。
